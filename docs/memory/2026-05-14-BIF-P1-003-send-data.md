## 总体架构判断

SEND_DATA 位于命令处理层，是 HEARTBEAT 之后的第一个数据上报命令。它涉及信号解析、测点映射、实时数据持久化，是 binterface 模块与 telemetry 模块的桥接班。

## 协议一致性判断

符合 B接口协议 2016 SEND_DATA 规范：
- 请求 Info.FSUCode/CollectTime → 提取
- 请求 xmlData Signal 数组 → SignalID/Value/Quality/Status
- 响应 Info ResultCode/Count
- 响应 xmlData 为空
- ResultCode 复用 B接口标准值（0/1002/2001/2003/5001），其中 2003 为 SEND_DATA 新引入（无有效测点数据）

## 修改前论证

**Why 新建 SendDataResult？**
HEARTBEAT 无业务模型（直接使用 CommandResult），但 SEND_DATA 需要表达 accepted/rejected 统计、逐项错误列表。SendDataResult 作为 Service 层结果模型，与 LoginResult 同级。

**Why 新建 SendDataService？**
Signal 解析 + 测点映射 + upsert 是独立业务逻辑，不适合放在 Handler 中。Handler 应仅负责校验/提取/委托/响应构建。

**Why 复用 LoginService.isLoggedIn()？**
与 HEARTBEAT 相同的校验策略，已通过 BIF-P1-001/BIF-P1-002 验证。

## 核心改动

### SendDataCommandHandler.handle()
```
context == null → 5001
infoXml == null/empty → 2001
FSUCode 为空 → 2001
isLoggedIn == false → 1002
extractCollectTime (可选)
委托 SendDataService.processData()
SendDataResult.isSuccess → 构建 Info: <ResultCode>0</ResultCode><Count>n</Count>
SendDataResult.fail → 透传错误码
异常 → 5001
```

### SendDataService.processData()
```
FSU 未注册 → 1002
xmlData 为 null → 2003
items 为空 → 2003
逐项 parseSignal → if valid → findByFsuIdAndPointCode → upsertRealtimeData
全部 rejected → 2003
部分 accepted → partial(accepted, rejected, errors)
全部 accepted → success(accepted, rejected)
```

### 新增 extractCollectTime()
`public static`，正则 `<CollectTime[^>]*>(.*?)</CollectTime>` 大小写不敏感

### parseNumeric/parseCollectTime public
工具方法从包可见改为 public，以便跨包测试

## 修改前论证

### 现状

- 项目已有完善的写入前论证（第四章）和写入后验证（第五章）规则
- 但缺少"操作记忆持久化"机制
- 每次操作的论证、验证、测试结果、遗留问题等仅在对话中存在，跨会话丢失
- 无统一的历史操作归档位置

### 方案

1. 创建 `docs/memory/` 目录作为操作记忆归档位置
2. 创建 `docs/memory/README.md` 作为索引
3. 在四份规则文件中追加"操作记忆写入规则"章节
4. 明确要求：任何操作（含只读）后必须写入记忆文件，否则任务未闭环

### 架构影响

无。规则文件属于项目规范，不参与编译、打包、运行。

## 核心改动

四份规则文件同步追加"操作记忆写入规则"，内容包括：
1. 记忆文件路径 `docs/memory/`
2. 命名规则 `YYYY-MM-DD-任务编号-简短任务名.md`
3. 记忆文件内容要求（13个字段）
4. 只读任务也需写入记忆
5. 索引维护要求
6. 闭环条件：未写记忆 = 未闭环

## 操作记忆规则说明

新规则属于**第4级约束**（流程闭环约束），高于写入后验证（第5章）：
- 写入后验证只验证当前任务产出是否正确
- 操作记忆写入确保跨任务可追溯
- 两者共同构成完整闭环
